# October Jam Kit

Быстрая техническая основа одиночного 2D-платформера для джема. Unity **6000.3.27f1**, Windows x64 / Linux x64, стандартный Built-in Renderer.

## Запуск

1. Unity Hub → Projects → Add → выбери `G:\GameJams\October`.
2. Открой `Assets/JamKit/Generated/Scenes/MainMenu.unity` и нажми Play.
3. Нажми **Explore world**. A/D или стрелки — движение, Space/W/↑ — прыжок, ЛКМ/J — удар, Tab — карта, Esc — пауза, R — перезапуск комнаты.

Можно запускать Sandbox прямо из редактора: приложение и интерфейс подключаются автоматически.

## Что готово

- Главное меню, пауза, настройки и технический экран завершения.
- Сохранение громкости, яркости мира, оконного/полноэкранного режима и качества между запусками.
- Отдельная громкость музыки и эффектов. Фоновая музыка по умолчанию отсутствует. Звуки прыжка и возрождения — тестовые тоны; замени их перед джемовой подачей.
- Движение с ускорением, прыжок переменной высоты, буфер прыжка и короткое время прыжка после схода с края.
- Следящая камера с границами, опасность, чекпоинт и возрождение.
- Три связанные комнаты с автоматическими двусторонними переходами и сохранением героя.
- Карта исследованного мира на Tab: посещённые комнаты, связи, текущая комната и положение героя. Исследование сохраняется между запусками.
- ArtTheme и SpriteStyle для смены спрайтов без изменения коллайдеров; префабы моделей и готовый шаблон новой комнаты.
- Здоровье героя, портрет и счётчик в HUD; ближний удар ЛКМ/J и тренировочная мишень в Gallery.
- Настраиваемый противник ближнего боя с патрулём, обнаружением, подходом, подготовкой атаки и смертью. Спрайты, Animator и звуки подключаются через профиль; пример — EnemyDemo.
- Мигание героя и врагов при уроне, с настройкой длительности и подключением полноценной Hurt-анимации: [инструкция](docs/damage-feedback.md).
- NPC с взаимодействием на E и сюжетные области: линейные диалоги с именами, портретами и паузой мира. [Как писать диалоги](docs/dialogues-and-npcs.md); пример — Story/DialogueDemo.
- Управление меню мышью и клавиатурой: Tab/Shift+Tab или стрелки, Enter/Space, Esc для возврата.

Яркость затемняет игровой мир, сохраняя читаемость UI. Качество меняет лимит кадров (30/60) и MSAA (выкл./4x). Чекпоинты комнат запоминаются в текущей сессии; перезапуск комнаты сбрасывает её чекпоинт. Между запусками сохраняются настройки и открытая карта; продолжения с последнего места пока нет.

## Как строить свою игру

Пошаговый учебник: [сцены и двусторонние связи](docs/level-building-guide.md). Оформление и бой: [спрайты, здоровье и удар](docs/art-and-combat.md). [Настройка врага и анимаций](docs/enemy-guide.md). [Стрелок и босс](docs/enemies-and-boss-design.md) остаются планом следующего этапа.

1. Для связанного мира скопируй одну из сцен WorldDemo через Save As; настрой WorldRoom, двери и WorldDefinition по [инструкции](docs/rooms-and-map.md). Для отдельного уровня можно скопировать Sandbox.
2. Добавь новую сцену в File → Build Profiles → Scene List. Укажи имя стартовой сцены в `playScene` на префабе `Assets/Resources/JamKitApp.prefab`.
3. Измени скорость, ускорение, высоту прыжка и временные допуски на `PlayerMotor` общего префаба `Generated/Player.prefab` (для WorldDemo). Изменение значений во время Play откатывается при выходе из Play.
4. Замени SpriteRenderer героя и платформ своей графикой. Коллайдеры и Rigidbody2D оставь отдельными от оформления. Земля использует слой Ground.
5. Для опасности, чекпоинта или выхода используй BoxCollider2D с Is Trigger и компонент RoomTrigger. Respawn Point у чекпоинта должен находиться над безопасной поверхностью.
6. Настрой `CameraFollow`: target, offset, min/max — это границы центра камеры.
7. Меню редактируются в префабе `JamKitApp`: обычные Canvas, Button, Slider, Toggle и Text. Привязки видны в `GameView`.

Герой в Sandbox сейчас является отдельным объектом сцены: параметры меняй на **Player в Hierarchy**. Сохранённый `Generated/Player.prefab` — исходная копия, изменения в нём автоматически в Sandbox не попадают. Для новых сцен можно перетащить этот префаб на сцену и назначить его Transform в `CameraFollow.target`.

### Фоновая музыка

Открой `Assets/Resources/JamKitApp.prefab`, выбери корневой JamKitApp и его AudioSource. Поле Audio Resource (AudioClip) оставлено пустым: прежний зацикленный тестовый гул отключён. Чтобы добавить мелодию, импортируй свой WAV/OGG/MP3 в Assets и перетащи его в это поле. Loop и Play On Awake уже включены. Компонент MusicChannel связывает громкость этого источника с ползунком Music volume. Одна мелодия будет продолжаться при переходе из меню в игру.

Кнопка Play загружает сцену из `GameApp.playScene` (теперь WorldHub). Для связанного мира используй `WorldRoom` и `RoomDoor`; подробная инструкция — [Комнаты и карта](docs/rooms-and-map.md). `RoomTrigger.Finish` по-прежнему открывает экран завершения; для обычного перехода нужен `RoomDoor`.

`Jam Kit → Generate starter scenes` **перезаписывает** содержимое Generated и префаб JamKitApp. Команда нужна для восстановления исходного шаблона; после своих изменений пользуйся сохранёнными сценами и префабами.

## Сборки

- `Jam Kit → Build Windows` → `Builds/Windows/JamKit.exe`.
- `Jam Kit → Build Linux` → `Builds/Linux/JamKit.x86_64`.
- Передавай всю папку сборки, включая JamKit_Data, UnityPlayer и остальные файлы рядом с исполняемым файлом.
- Для Linux при необходимости выставь право запуска: `chmod +x JamKit.x86_64`.
- Наличие Linux-сборки не заменяет проверку на Linux. Здесь доступна проверка запуска Windows.

Сборки команд меню создаются с Development Build для удобства подготовки. Для джемовой подачи можно снять Development Build в Build Profiles и собрать обычным способом.

## Проверка

Отдельная проверка здоровья, HUD, атаки, стены, мишени и сохранения здоровья при переходе: `JamKit.exe --combat-smoke -batchmode -logFile combat-smoke.log`. Результат — QA/combat-result.txt. Без -batchmode создаётся скриншот боя и здоровья.

Windows-сборка поддерживает запуск `JamKit.exe --jam-smoke -batchmode -logFile smoke.log`. Он проверяет меню, ввод, прыжок, паузу, настройки, чекпоинт, опасность, падение, завершение и перезапуск. Результат сохраняется в папке QA рядом с exe; код выхода 0 означает успех. Если убрать `-batchmode`, проверка также сохранит скриншоты интерфейса.

Перед публикацией проверь мышь и клавиатуру в меню, звук, изменение размера окна и полноэкранный режим вручную. Автоматический запуск не оценивает удобство управления и внешний вид.
